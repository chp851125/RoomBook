# RoomBook 設計取捨、已知限制與未完成項目

## 設計取捨

- **JSON + 記憶體**：啟動時整檔載入記憶體，異動以「寫暫存檔再取代」寫回；單鎖保護，簡單且夠用於公司內部規模（數十人、數千筆預約）。代價是每次寫入都重寫整個檔案，資料量成長後應改接資料庫（見 README）。
- **Repository 回傳複本**：呼叫端改了物件不會影響記憶體，必須 `Update` 才生效，並以 `Version` 做樂觀並行控制。
- **「每間會議室一把鎖」只在單一程序內有效**：衝突檢查加寫入在 `RoomLockProvider` 的鎖內完成；若部署成多個執行個體，需改用資料庫約束／交易。
- **週期預約不預先展開**：規則存 `BookingSeries`，顯示與衝突檢查時動態展開（最多 52 次）。簽到、延長、提前結束、提醒、釋出時才把該次「實體化」成一筆 `Booking`（`ExpandSeries` 之後會略過它）。
- **佔用時段**：只有 Confirmed 與 Pending 佔用；Pending 先保留時段，駁回後才釋出。
- **時間**：UTC 儲存、顯示轉台北；`ITimeProvider` 集中取得。營業時段、假日、週期預約的時刻是台北本地，使用時再轉 UTC。
- **範例資料每天重新產生（Development）**：因為日期相對於執行當天，`SeedData/` 在 Git 會每天有差異；非 Development 不會重新產生。
- **Email 為模擬**：寫 `.eml` 到 `outbox/` 並記 `EmailLog`；沒有真的寄出。種子裡的 8 筆 Email 紀錄只有檔名、沒有實體檔案。
- **看板頁免登入**：只顯示主題（`Display.ShowTitle` 可關）與預約人姓名；以網址（GUID）識別，沒有額外的存取權杖。

## 已知限制

- **自動釋出只處理「剛超過簽到時窗、回溯 30 分鐘內」的預約**：系統停機超過這段時間，漏掉的不會補記違規。
- **違規點數不會自動歸零**：暫停到期後下一次違規會立刻再暫停；管理員可在使用者頁「解除暫停並清除違規點數」。
- **強制變更密碼只在登入後導向「個人設定」**，沒有在每個頁面強制攔截。
- **管理員審核週期預約是整組一次核准／駁回**，不能只核准其中幾次。
- **每人未來預約上限**：一組週期預約算 1 筆，不是展開後的次數。
- **修改預約只支援尚未開始的單次預約**；週期預約只能單次改時間或單次取消，不能整組修改（需取消後重建）。
- **延長不受「單次最長時數」限制**，只檢查進行中、營業時段與後續衝突（依需求第 9 條）。
- **CSP 保留 `unsafe-inline`**（頁面有少量 inline script／事件處理）；若要更嚴格，需改為 nonce。
- **CSRF**：依賴 Razor Pages 預設的 Antiforgery；Cookie 的 `Secure` 設為 `SameAsRequest`，正式環境請走 HTTPS。
- **快取與效能**：`Query` 為記憶體內線性掃描；統計儀表板每次請求即時計算。
- **沒有測試專案、沒有 CI**（依專案需求）；驗證靠手動與 `--generate-seed` 的自我驗證。
- **手機版畫面**：以 Bootstrap RWD 實作，開發期間主要以頁面內容與 HTTP 回應驗證，未逐頁做視覺截圖比對。
